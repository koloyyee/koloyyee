## Why Monitoring?
One thing I learned from my experience as a chef is that it is all about control. Being able to monitor the current state of the machine means it will be easier for me to control the outcome.

For weeks and months, I had heard of Prometheus and Grafana, but I didn't have a clue what they did. So, I went to YouTube to learn about them (here are the videos for [Prometheus](https://www.youtube.com/watch?v=h4Sl21AKiDg) and [Grafana](https://youtu.be/z8Sfq8Tz7mg?si=aM3t6Otb3xaKeWGI)), but how do I set them up? Also, Tailscale is a private network... how can I access it from a public network? This week, I'll be talking about monitoring a homelab with Prometheus, Grafana, and Cloudflare Tunnel.

A homelab isn't complete without observability. I want to know:
* Is my Dell laptop healthy? (CPU, RAM, disk)
* Are my pods running? (Calibre-Web, Immich, Ngnix Proxy Manager)
* Can I check this from anywhere in the world?
The answer: Prometheus + Grafana + Cloudflare Tunnel.

**The Stack**
```sh
Prometheus     → scrapes and stores metrics every 15 seconds
Grafana        → visualizes metrics via dashboards
Node Exporter  → collects Dell laptop hardware metrics
kube-state-metrics → collects K8s pod/deployment health
Cloudflare Tunnel  → exposes Grafana publicly, no open ports
```

## Helm
### What is Helm?
Helm is a package manager for Kubernetes applications. Instead of writing and managing dozens of YAML manifests yourself, Helm bundles everything into a **chart** (a pre-packaged collection of manifests with sensible defaults) that you can install with a single command. One `helm install` deployed Prometheus, Grafana, Alertmanager, Node Exporter, and all their configurations — something that would have taken hundreds of lines of hand-written YAML to replicate.

### Step by step
Step 1 — Install Helm
Helm is the package manager for Kubernetes. Install it on macOS:
```sh
brew install helm
```

Step 2 — Deploy Prometheus + Grafana
One command deploys the entire monitoring stack via `kube-prometheus-stack`:
```sh 
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# Install the full monitoring stack
helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --create-namespace
```

This single Helm chart installs:
* Prometheus (metrics collection)
* Grafana (dashboards)
* Alertmanager
* Node Exporter (hardware metrics)
* kube-state-metrics (pod/deployment health)
* Pre-built Kubernetes dashboards

Watch everything come up:
```sh
kubectl get pods -n monitoring -w
```
All pods should reach Running within a couple of minutes.

Step 3 — Set Up Cloudflare and Configure DNS
Cloudflare Tunnel lets you expose Grafana publicly without opening any ports on your router or firewall. Traffic flows outbound from your homelab to Cloudflare — no inbound rules needed.

**Register on Cloudflare and migrate DNS from domain registrars (Namecheap, Porkbun, etc):**
1. Sign up at `cloudflare.com`
2. Add site → enter `<your_domain>` → Select Free plan
3. Cloudflare scans and imports your existing DNS records — verify they look correct
4. Cloudflare gives you two nameservers e.g.:
   ```
   aria.ns.cloudflare.com
   bob.ns.cloudflare.com
   ```
5. Log into Namecheap → Domain List → Manage `<your_domain>`
6. Nameservers → switch to **Custom DNS** → paste in Cloudflare's two nameservers → Save
7. Wait 10-30 minutes for propagation — no domain transfer needed, domain stays at Namecheap

**Clean up stale DNS records in Cloudflare and add correct ones:**

| Type | Name | Content | Proxy |
|---|---|---|---|
| A | npm | `<tailscale_server_ip>` | DNS only |
| CNAME | books | `npm.<your_domain>` | DNS only |
| CNAME | photos | `npm.<your_domain>` | DNS only |
| CNAME | www | `<your_github_username>.github.io` | Proxied |

> **Important:** Tailscale IPs must be set to **DNS only** (grey cloud). Cloudflare proxy blocks private/reserved IPs with Error 1002.

**Create the Tunnel:**
1. Cloudflare dashboard → **Zero Trust** → Networks → Tunnels → **Create a tunnel**
2. Choose **Cloudflared** → Next
3. Name it `homelab` → Next
4. Select **Docker** from the OS dropdown to reveal the token:
   ```
   docker run cloudflare/cloudflared:latest tunnel --no-autoupdate run --token eyJh...
   ```
5. Copy the token after `--token` — **treat it like a password, never expose it**
6. Don't run the Docker command — we deploy via K3s instead

---

Route the tunnel:
* Subdomain: grafana
* Domain: <your_domain>
* Type: HTTP
* URL: monitoring-grafana.monitoring.svc.cluster.local:80

This URL is the internal K3s DNS name for the Grafana service. Because cloudflared runs inside the cluster, it can reach the service directly.

Step 4 — Deploy cloudflared as a K3s pod

Store the token as a Secret — never hardcode it:

`cloudflared-secret.yml`
```yml
apiVersion: v1
kind: Secret
metadata:
  name: cloudflared-token
  namespace: monitoring
type: Opaque
stringData:
  token: "<your-tunnel-token>"
```

`cloudflared.yml`
```yml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: cloudflared
  namespace: monitoring
spec:
  replicas: 1
  selector:
    matchLabels:
      app: cloudflared
  template:
    metadata:
      labels:
        app: cloudflared
    spec:
      containers:
      - name: cloudflared
        image: cloudflare/cloudflared:latest
        args:
        - tunnel
        - --no-autoupdate
        - run
        - --token
        - $(TUNNEL_TOKEN)
        env:
        - name: TUNNEL_TOKEN
          valueFrom:
            secretKeyRef:
              name: cloudflared-token
              key: token
```
Apply in order:
```sh
kubectl apply -f cloudflared-secret.yml
kubectl apply -f cloudflared.yml
```
Verify the tunnel connected:
```sh
kubectl logs deployment/cloudflared -n monitoring
# Look for:
INF Connection established connIndex=0
INF Connection established connIndex=1
```

Step 5 — Get Grafana password

The password is stored as a K8s Secret by Helm:
```sh
kubectl get secret -n monitoring monitoring-grafana \
  -o jsonpath="{.data.admin-password}" | base64 --decode
```
Login at `https://grafana.<your_domain>` with admin and the decoded password.

Step 6 — Share Public Dashboards

Create `grafana-values.yml` to configure Grafana:
```yml
grafana:
  grafana.ini:
    server:
      root_url: https://grafana.<your_domain>
      serve_from_sub_path: false
```
Without this step the Grafana root url will be `localhost:3000` instead of your grafana url.

In your terminal run:
```sh
helm upgrade monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --reset-values \
  -f k3s/grafana-values.yml
```

Grafana supports public dashboards — no login required for viewers.
For each dashboard:
1. Open the dashboard
2. Click Share icon
3. Public dashboard tab
4. Enable → copy the public link

Recommended dashboards to share:

| Dashboard | What it shows |
| :--- | :--- |
| Node Exporter / Nodes | Dell laptop CPU, RAM, disk, network |
| Kubernetes / Compute Resources / Cluster | Full cluster resource overview |
| Kubernetes / Compute Resources / Namespace (Pods) | Per-namespace pod resources |
| Kubernetes / Compute Resources / Node (Pods) | Per-node pod breakdown |

**Architecture**
```sh
Anyone, anywhere
       ↓
https://grafana.<your_domain>
       ↓
Cloudflare (SSL, DDoS protection)
       ↓
Cloudflare Tunnel
       ↓
cloudflared pod (K3s, namespace: monitoring)
       ↓
monitoring-grafana service (ClusterIP)
       ↓
Grafana pod → Prometheus pod → my Dell's metrics
```
### Be Careful!

** Helm runs on your Mac and deploys to K3s**

Helm reads ~/.kube/config and talks to your remote K3s cluster over Tailscale — same as kubectl. You never need to SSH into the server to deploy.

Prometheus is not public-facing 

Prometheus acts as the backend by scraping and storing metrics, while Grafana acts as the frontend. Only expose Grafana publicly.

Access Prometheus internally if needed:
```sh
kubectl port-forward svc/monitoring-kube-prometheus-prometheus -n monitoring 9090:9090
```
Cloudflare Tunnel token is sensitive Anyone with your tunnel token can run a connector and intercept traffic. Always store it as a Kubernetes Secret, never hardcode it in a manifest or commit it to Git.

Internal K3s DNS for service URLs When routing the tunnel to Grafana, use the full internal DNS name:
`monitoring-grafana.monitoring.svc.cluster.local:80`
Format is: `<service-name>.<namespace>.svc.cluster.local:<port>`

Last but not least, add `cloudflared-secret.yml` to .gitignore to avoid leaking your cloudflare token:
```sh
echo "cloudflared-secret.yml" >> .gitignore
```

End State
```sh
grafana.<your_domain>  → Cloudflare Tunnel → Grafana (public, anywhere)
books.<your_domain>    → Tailscale only    → Calibre-Web
photos.<your_domain>   → Tailscale only    → Immich
```
